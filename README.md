## What it does

`water_usage_analyzer.py` analyzes irrigation records across 8 crops, 5 farming
regions, 4 irrigation methods and 12 months. It:

1. Generates (or loads) irrigation records as CSV
2. Cleans and validates them — duplicates, missing values, negative values,
   invalid months and outliers are removed
3. Computes totals, percentage shares and water intensity (m³ per hectare)
   by crop, region, method and month
4. Produces 5 charts and summary CSVs in `output/`

## Key findings

- 612 raw records cleaned down to **550 valid records**, covering 1,749.23 ha
  and 1,292,341 m³ of water
- Most water-intensive crops: **Sugarcane (1,581.8 m³/ha)** and
  **Rice (1,158.0 m³/ha)** — together 41.6% of all water on only 22.5% of the area
- Highest-intensity regions: **Warangal (850.4 m³/ha)** and
  **Karimnagar (828.2 m³/ha)**; lowest: Mahabubnagar (595.3 m³/ha)
- Peak months: **October (14.9%), November (12.3%) and June (11.8%)** —
  39.0% of annual use together
- **Flood irrigation (1,365.0 m³/ha) uses 2.8× as much water per hectare as
  drip (485.6 m³/ha)**
- A conservative estimate: cutting flood-irrigation water by 30% would save
  about **161,227 m³ (12.5% of total use)**

Note: the dataset is simulated by the program itself (fixed random seed 16),
as stated in the report. The same program runs unchanged on a real CSV file
with the same columns.

## Usage

```bash
python water_usage_analyzer.py
```

Charts and summary tables are saved in `output/`. If
`irrigation_records_raw.csv` already exists it is reused; delete the CSV
files to regenerate the dataset from scratch (seed 16, so the result is
identical).

## Testing

```bash
python -m unittest discover -s tests -v
```

12 tests, all passing on the verified run: cleaning rules (duplicates,
missing, negative, invalid month, unknown category, non-numeric, outlier
rule), grouping/monthly/matrix arithmetic, deterministic generation
(612 rows → 550 clean), and a fresh-directory end-to-end run that checks
all 5 charts, 4 summary CSVs and the headline totals.

One real bug was found by these tests and fixed: `clean_data` crashed with
`IndexError` when every input row was rejected (empty list passed to the
quartile calculation). A three-line guard now returns an empty result in
that case. The fix changes no result on the real data.

## Limitations

- Simulated dataset (seed 16), not real farm measurements; single year only.
- Crop and irrigation method are strongly linked, so their effects cannot
  be fully separated.
- Rainfall, soil, groundwater depth, yield and cost data are not included.
- `save_csv` assumes at least one row; duplicate detection compares raw
  rows before text normalisation, so rows differing only by case/spacing
  are not counted as duplicates.
- Statistics functions expect cleaned, typed records (as produced by
  `clean_data`); raw CSV strings will raise a type error.
